# 科研经费拨款核对（Flask + Docker Compose）

上传拨款表、归属表、归口表三份 CSV，按**拨款日**做两层内连接，核算各统计单位的
实际合计与实际入表次数，并列出漏计、多计的单号。

## 目录结构

```
.
├── app/
│   ├── reconcile.py          # 核对引擎：CSV 校验、按日整批扫描有效期、加权计数
│   ├── web.py                # Flask 路由与页面
│   ├── templates/            # 上传页 / 结果页 / 错误页
│   └── samples/              # 三份可直接试跑的样例 CSV（页面可下载）
├── tools/
│   ├── bench_compare.py      # 优化前后对比基准（同一批数据跑两个引擎）
│   └── baseline_reconcile.py # 优化前的原始引擎，仅供对比
├── tests/test_reconcile.py   # 自测脚本（引擎 + Flask 端到端）
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
└── README.md
```

## 启动方式

### Docker Compose（交付方式）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

容器以非 root 用户运行 gunicorn（2 worker × 4 线程），带健康检查。
停止：`docker compose down`。

### 无 Docker 时本地运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:8000 app.web:app     # 或 flask --app app.web run
```

## 输入格式（UTF-8，首行表头，列顺序固定）

| 文件 | 列 |
|---|---|
| 拨款表 | `单号, 项目号, 拨款日, 金额_分` |
| 归属表 | `行号, 项目号, 学院码, 起日, 止日` |
| 归口表 | `行号, 学院码, 统计单位, 起日, 止日` |

- 日期 `YYYY-MM-DD`；有效期为 **[起日, 止日)**，含起日、不含止日。
- 金额单位为分、非负整数；单号与两表行号各自唯一（违反即整次退回）。
- 外键不存在（如项目号在归属表无任何行）不算输入错误，按漏计处理。

## 核对规则

一条完整匹配路径 = 一条拨款日有效的归属行 + 一条该归属学院下拨款日有效的归口行。

1. **第一层（归属层）**：`项目号` 相等且拨款日落入归属有效期。命中 0 行 →
   漏计，断在**归属层**。
2. **第二层（归口层）**：对每条命中归属行的`学院码`，找拨款日有效的归口行。
   全部学院都无有效归口 → 漏计，断在**归口层**（页面注明已命中几条归属）。
3. 完整路径数 = **实际入表次数**：0 为漏计，1 为正常，>1 为多计。
4. **同一统计单位的不同匹配路径分别计入**，金额按路径数倍乘。
5. 多计页面给出两条匹配路径示例，各自标出归属表行号与归口表行号，
   并按统计单位列出路径数分布。

### 批量核对：整批复用有效期（优化重点）

历史数据里同一项目的单据分散在许多日期，逐笔核对时会反复线性扫描归属/归口底表。
现行引擎按**拨款日升序**对底表做一次扫描：

- 底表每行只在**起日进入**活动集、**止日退出**活动集各一次，整批拨款共用；
- 活动集按 `项目号 → 学院 → 条数`、`学院 → 统计单位 → 条数` 聚合，
  单笔拨款直接读取当日命中的学院与统计单位，不重扫历史行；
- 同一拨款日、同一项目的分布只计算一次（页面上的“分布复用”次数），
  该日的多笔拨款各自入表、各自倍乘金额；
- 只有多计单需要展示示例路径时才读取活动行，且取够两条即停，
  仍按归属表、再按归口表的**上传行序**取前两条；
- 统计口径、报表字段、错误整批退回行为均与优化前完全一致。

页面结果上方会显示本次核对实际查看的底表行事件数，便于和旧逻辑对照。

### 为什么合计与次数不需要枚举匹配路径

设某笔拨款在学院 c 命中 `n_attr(c)` 条归属行、该学院拨款日有 `n_jur(c)` 条归口行，
归口行 j 指向统计单位 u，则：

```
该归口行对应的路径数 = n_attr(c)
单位 u 的入表次数  += n_attr(c)
单位 u 的合计      += n_attr(c) × 金额
```

引擎按“学院 → 统计单位”聚合，只做加法与乘法，**不构造归属×归口的笛卡尔积**。
时间复杂度只与命中的归属行、归口行数量有关，与路径总数（乘积）无关。
自测中 600 归属 × 800 归口 = 48 万条路径，引擎仅构造 2 个用于页面展示的
示例路径对象即完成全部合计与次数计算，底表只扫描 600 + 800 步。

### 优化前后对比（可复现）

```bash
python3 -I tools/bench_compare.py    # 同一批数据分别跑优化前/后的引擎
```

数据：7910 笔拨款分布在约 2900 个不同日期，归属 4800 行、归口 1200 行且有效期大量重叠。

| 指标 | 优化前（逐笔扫描历史行） | 优化后（按日整批扫描） |
|---|---|---|
| 底表行检查次数 | 8,098,480 | **7,020**（归属 5,552 + 归口 1,468） |
| 耗时 | 7.7s | **2.1s** |
| 报表 | 基准 | 与基准逐项一致 |

行检查降低约 **1150 倍**；两个引擎在同一批数据上的合计、次数、漏计/多计明细完全一致。
另用 300 组随机数据 + 首尾相接边界做差分测试，优化前后报表亦逐项一致。

## 错误处理（整次退回）

任一文件存在问题时，本次核对不产生任何部分结果，HTTP 400 进入错误页，
逐条列出**文件名 + CSV 物理行号 + 原因**，三个文件的错误一次性全部返回。
覆盖：表头不符、列数不符、日期格式、金额非整数/负数、必填为空、
单号或行号重复、有效期起日不早于止日、空文件、非 UTF-8、NUL 字节、缺传文件。

## 自测

```bash
python3 -I tests/test_reconcile.py     # 需先 pip install Flask
python3 -I tools/bench_compare.py      # 优化前后对比（约 10s）
```

脚本与数据目录分离并以 `-I` 隔离模式运行，避免从数据目录加载同名模块。

### 实测结果（本机，Python 3.11 + Flask 3.0.3）

- 自测断言全部通过（`tests/test_reconcile.py`），覆盖：
  - 基础两层连接、漏计（归属层 / 归口层）、多计、菱形连接汇入同一单位分别计入；
  - 半开区间边界：两层各自验证起日当天命中、止日当天失效；
  - **首尾相接**：A 止日等于 B 起日，换窗当天只命中 B（不重不漏）；
  - **同日同项目多笔**：分布复用一次，10 笔各自入表并逐笔累加金额；
  - **重叠归属**：同项目 3 条并行归属（含同学院 2 条、跨学院 1 条）→ 3 条路径、
    金额按路径倍乘；
  - **大量重复匹配**：600 × 800 = 480,000 条路径，次数与合计精确，
    底表仅 600 + 800 步扫描、示例仅读取 3 行；
  - 13 类输入校验，均带文件与行号，多文件错误一次返回；
  - Flask 端到端：正常上传 200、错误输入 400 整次退回、缺文件 400、样例下载。
- 差分测试：300 组随机数据 + 相接边界，优化前后报表逐项一致。
- 用 gunicorn 按容器的启动参数实起服务、curl 真实上传：
  - 样例三表 → HTTP 200，多计 4 笔、总入表 11 次、总合计 38,000.00 元，
    页面显示“底表扫描 …共 14 次行事件检查”；
  - 首尾相接批次 → 200，接缝日只命中后一段（U2 一次）；
  - 错误金额 → HTTP 400，整次退回并定位“拨款表 第 2 行”；
  - 缺文件 → HTTP 400。
  （本机无 Docker daemon，改用与镜像相同的依赖版本和 gunicorn 命令，
  按镜像的 `/app` 目录结构实跑。）

## 未完成项 / 已知限制

1. 交付环境没有 Docker daemon，`docker compose up` 未在本机实跑；
   已通过 compose YAML 解析校验，并用同版本 Flask/gunicorn 按镜像目录结构做了等价实跑。
2. 结果仅在当次页面展示，未做持久化、历史记录或报表导出（如 Excel）。
3. 文件全量读入内存，上传上限 16MB；未实现流式解析。
4. 有效期扫描需先把事件按日期排序（O(n log n)）；拨款日跨度极大、底表行数极多时，
   内存中会同时保留两套活动聚合与事件表。当前 16MB 上限内实测充裕。
5. 金额只接受整数分，不接受浮点“元”；无登录鉴权与多用户隔离。
6. 自测为独立断言脚本，未引入 pytest，前端无浏览器自动化测试。
